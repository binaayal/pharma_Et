Medha — Pharmacy System

Visual prototype for the V1 mobile app and web admin console. Hand this file to Claude Code alongside /docs.

What this file is — and is not

This is visual and UX intent: what every screen looks like and how they connect, with realistic Ethiopian pharmacy sample data. It contains no real logic. The source of truth for behaviour and data contracts is the documentation:

  • 02-srs.md — requirements + acceptance criteria
  • 04-system-design.md — data model, sync envelope, RBAC/RLS
  • 05-qa-and-test-strategy.md — the guardian suites that gate every merge

A screen that looks right but violates the sync contract or tenant isolation is still wrong. Match this look; build behaviour to the docs.

New in this revision

  • New pharmacy request → phone-based sign-up request; we review and open the account (anti-abuse gate). Reviewed on the web console's Sign-up requests page.
  • Subscription ended → a blocking lock screen; data stays safe, prompts payment proof.
  • Submit payment proof → owner uploads the Telebirr/CBE screenshot; it lands in web Payment verification.

Screen → requirement map

  • Request / Login → FR-2 (auth, offline login); onboarding gate is platform-side
  • Subscription ended / Payment proof → subscription state (BR-1.3) + manual verification (Vision §4)
  • Sell / Payment / Receipt → FR-4 (POS), FR-3 (FEFO, negative stock)
  • Dispense controlled → FR-4 psychotropic rules + FR-6 (ledger)
  • Inventory / Product / Goods receipt → FR-3, FR-7
  • Cash-up / Reports / Ledger → FR-8, FR-6
  • Branches & staff / Settings → FR-1, FR-2, FR-10
  • Web console → FR-1, sign-up review, payment verification, subscription control
